# 試作品 v0（この端末だけで動く版）

画面と業務の流れを確かめるための試作品です。**本番のシステムではありません。**

- `index.html` の1ファイルだけで動きます。サーバー・インターネット・外部のサービスは使いません
- データは、開いた端末のブラウザの中（localStorage）にだけ保存されます
- 施設名・氏名・業務はすべて架空です。**実在の職員・入居者の情報は入力しないでください**
- 見た目は「引き算のデザイン（v2）」です（基準：`../docs/product/design-guidelines.md`、調べたこと：`../docs/product/benchmark-research.md` 第2.15節）

## 開き方

1. `index.html` をパソコンに保存する
2. ダブルクリックで開く（Chrome・Edge・Safari などの最新版）
3. 画面上部の黒い帯の「利用者」で、施設長・事務長・介護主任・職員を切り替える

スマホの画面は、ブラウザの幅を狭くするか、ファイルをスマホに送って開くと確かめられます。
ブラウザの保存が使えない環境（一部のプレビュー画面など）では動きますが、閉じると元に戻ります（上部の帯に「この画面では保存されません」と出ます）。

## 5分で試す流れ

| 順 | 利用者 | やること | 確かめたいこと |
|---|---|---|---|
| 1 | 高木 誠（施設長） | ホームを見る | 期限超過・承認待ち・未提出・担当者未設定が一目で分かるか |
| 2 | 山田 花子（介護職員） | 「今日のやること」から研修レポートを提出（写真かファイルを選ぶ）。差し戻された受診報告を出し直す | 迷わず出せるか（「提出する」から3回のタップ） |
| 3 | 佐藤 健一（介護主任） | 「承認待ち」で承認・差し戻し。「提出」→「感染症の研修レポート」で催促・代理登録 | 一覧に戻らずに次の件へ進めるか |
| 4 | 田中 由美（事務長） | 行政提出の業務を、控えを付けて完了報告。提出物をまとめて承認 | 控えがないと完了にできない流れが分かりやすいか |
| 5 | 高木 誠（施設長） | 行政提出を承認 | 人が承認して初めて完了になるか |
| 6 | だれでも | 上部の「1日進める」 | 毎日のチェックリストと自動の督促が動くか |

最初の状態に戻すときは、上部の「この試作品について」→「最初の状態に戻す」。

## 入っているもの（試作品の範囲で動く）

- 利用者の切り替え（施設長・事務長・介護主任・職員）
- 管理者のホーム（要対応、あなたのやること、今日まで、期限が近い、委員会・研修の予定、自動チェック）
- 職員のホーム「今日のやること」（差し戻し → 期限超過 → 今日まで → 新しい依頼 → チェックリスト → 今週の予定）
- 提出の流れ（1画面に1つ。健康情報などファイルを受け取らない区分は「済んだかどうか」と日付だけ）
- 提出状況表（絞り込み、催促、代理登録、対象外、未提出者一覧の印刷）
- 承認・差し戻し（その場で次の件へ。提出物はまとめて承認）、ほかの人が確認する件の一覧
- 業務・依頼の作成、着手、完了報告、保留と解除、担当の設定
- 行政提出の控えの登録（控えがないと完了報告できない。完了には人の承認が必要）
- 毎日のチェックリストの自動作成（同じ日の分は1件だけ）、日付を進めたときの自動の督促と、声かけのお知らせ
- 通知（画面の中だけ）、操作履歴
- チェックリストの「元に戻す」、知らせの「閉じる」（知らせは時間では消えません）

## 入っていないもの（未実装。完成扱いにしない）

- 本物のログインと権限管理（名前を選ぶだけ。見える範囲は簡易版）
- 法人・施設ごとのデータ分離、暗号化、バックアップなどのセキュリティ
- メール・スマホへの通知、まとめ送信、受信時間帯
- 書類管理、委員会・研修の登録画面、年間業務の登録画面、年度更新、CSV、はじめての設定
- AI アシスタント
- ファイルの中身の保存（ファイル名だけを記録します）、提出の途中の内容の自動保存

## 本番の設計との関係

この試作品は画面と流れの確認用で、本番の基盤（`../docs/` の設計：PostgreSQL の RLS による分離、権限、監査など）とは別物です。コードは本番に流用しません（`../docs/development/technical-decisions.md` の TD-078）。

試作品で仮に決めた動き（施設での確認が必要）：

- 前日までに終わらなかった毎日のチェックリストは「期限超過」に数えず、自動チェックで「未実施」として知らせる（TD-079）
- ファイルを受け取らない区分で「まだ」と答えたときは、提出扱いにしない（TD-080）
- 期限が先の提出依頼も、本人が一度開くまでは「新しい依頼」に出す（TD-081）
- 管理者のホームに「あなたのやること」、承認待ちの画面に「ほかの人が確認する件」を出す（TD-082）
- 職員のホームで目立つ色のボタンは、一番上のカードだけにする（TD-083）
- 見た目を「引き算のデザイン（v2）」に改め、提出の流れの間は下部のタブを出さない（TD-084〜TD-089）

## 動作確認（開発者向け）

リポジトリの直下で次を実行します。Playwright と Chromium が必要です。

```
node ai-facility-partner/prototype/tests/smoke.cjs
```

主な流れを100項目以上確かめます（エラーが出ないこと、外部への通信がないこと、文字が16px以上・ボタンの高さが44px以上であること、画面に見えている全部の文字のコントラストが4.5:1以上であることを含む）。
