# 運用ガイド（草案）

> 運用担当者（Q5）が決まり次第、担当者名・連絡先・手順の詳細を確定する。

## 1. 役割分担

| 役割 | 担当 | 主な業務 |
|---|---|---|
| サービス運営責任者 | 当社（未定） | 障害・情報漏えい時の判断、施設への連絡 |
| システム運用担当 | 当社（未定） | 監視、リリース、バックアップ・復元、権限付与（当社側） |
| 施設管理者 | 施設長・事務長 | 職員の登録・停止、役割割当、施設設定、権限の棚卸し |

## 2. 定常運用

| 頻度 | 作業 | 担当 |
|---|---|---|
| 毎日 | エラー監視・定期処理の実行結果確認 | 当社 |
| 毎週 | 依存部品の脆弱性情報の確認と更新 | 当社 |
| 毎月 | AI 利用量・費用の確認、ストレージ容量の確認 | 当社・施設 |
| 四半期 | 復元訓練、施設の権限棚卸し（不要な役割・退職者の確認）、当社スタッフの権限確認 | 当社・施設 |
| 年1回 | 祝日マスタの更新、AI 事業者の条件（データ保持・学習利用・処理地域）の再確認、ガイドライン改定の確認、要件候補一覧の見直し | 当社 |
| 年度末 | 翌年度の年間業務作成の案内 | 施設 |

## 3. アカウントの管理

| 場面 | 手順 |
|---|---|
| 入職 | 職員台帳に登録 → 必要な場合のみ招待（ログイン可能に）→ 役割割当 |
| 異動 | 所属（部署・役職）の期間を更新。役割の見直し |
| 退職 | 退職日を登録 → 当日ログイン停止・セッション失効 → 引継ぎ対象の一覧を確認して担当を変更 |
| パスワード忘れ | 本人が再設定。メールのない職員は管理者が再設定を発行（記録付き） |
| 端末の紛失 | 管理者が対象ユーザーのセッションを失効。必要に応じ一時停止 |

## 4. 当社による施設データへのアクセス（障害対応時のみ）

1. 施設から問い合わせ、または障害の検知
2. 当社担当者が理由を添えてアクセスを申請
3. 施設長（または法人管理者）が承認（期限付き、既定24時間）
4. アクセス中の全操作を記録
5. 期限到来で自動失効。対応内容を施設に報告

## 5. バックアップ・復旧

| 項目 | 内容（実証期の目標、仮） |
|---|---|
| バックアップ | DB：日次＋時点復元（7〜14日）、ファイル：版保持 |
| 復旧時間の目標（RTO） | 24時間以内 |
| 失ってよいデータ量の目標（RPO） | 24時間以内（時点復元により実際は数分程度） |

復旧手順：
1. 障害範囲の特定（DB、ファイル、アプリ、外部サービス）
2. アプリ不具合なら直前の版へ戻す
3. データ破損なら、破損前の時点を特定して**別の DB に**時点復元
4. 復元した DB で件数・整合性チェックを実行
5. 切替え、または必要なデータのみ戻す
6. 施設へ報告、原因と再発防止策を記録

AI 事業者・メール送信が停止した場合：業務は手作業で継続可能（AI 機能は停止表示、通知は再送）。

## 6. 障害・セキュリティ事故の対応

| 区分 | 例 | 対応 |
|---|---|---|
| 重大 | 他施設のデータが見えた、情報漏えいの疑い、全面停止 | 直ちに該当機能を停止 → 運営責任者へ連絡 → 影響範囲の調査 → 施設へ連絡 |
| 中 | 一部機能の停止、通知の未送信 | 当日中に対応、施設へ連絡 |
| 軽 | 表示の不具合 | 通常の改修 |

個人データの漏えい等が発生した場合：
- 当社は施設（個人情報の取扱いを委託した事業者）に速やかに報告する
- 個人情報保護委員会への報告・本人への通知の要否と期限は、法令・ガイドラインに従い施設と協議して対応する（報告期限などの詳細は**専門家に確認**し、本書に追記する）

## 7. データの出力・削除

| 場面 | 手順 |
|---|---|
| 施設からの出力依頼 | 権限者が画面から出力（CSV＋ファイル一式）。出力は記録 |
| 解約 | 出力データを提供 → 契約で定めた期間経過後に削除 → 削除完了を報告。バックアップは保持期間の経過で消去されることを説明 |
| 保存期限の到来 | 通知 → 施設が確認して削除（自動削除はしない） |

## 8. 施設の追加（実証後）

1. 契約・プランの登録（当社）
2. 法人・施設の作成、業態の選択（当社）
3. 施設長の招待
4. 初期設定の支援（`product/user-flows.md` 第1章）
