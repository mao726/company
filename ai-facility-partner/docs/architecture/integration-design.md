# 外部連携設計

## 1. 方針

- 最初から外部連携は作らない。**CSV の取込・出力を優先**する
- 連携は `packages/integrations/` に「連携アダプタ」として追加し、業務モジュールは共通の取込・出力処理を通して利用（連携先が変わっても業務コードを変えない）
- 各サービスについて、**API の有無・利用条件・連携許可（契約上の可否）を個別に確認**してから着手する
- 連携の認証情報（APIキー等）は施設ごとに秘密情報管理へ保存し、画面・ログに表示しない

## 2. CSV 取込・出力（MVP）

| 対象 | 取込 | 出力 | フェーズ |
|---|---|---|---|
| 職員（氏名、職員番号、部署、役職、雇用形態、メール/ログインID） | ○ | ○ | 2 |
| 部署・役職マスタ | ○ | ○ | 2 |
| 年間業務（シリーズ） | ○ | ○ | 2 |
| 業務一覧（期間・状態で絞り込み） | — | ○ | 3 |
| 提出状況（依頼別：職員×状態） | — | ○ | 3 |
| 委員会・研修の実施記録、研修出欠 | — | ○ | 3 |
| 書類台帳（ファイル一覧） | — | ○ | 3 |
| 操作履歴 | — | ○ | 3 |

取込の流れ：
1. テンプレートCSV（列見出し付き、UTF-8／Excel 対応のため Shift_JIS も受付）をダウンロード
2. アップロード → 検証（必須項目、重複、存在しない部署等）→ **結果のプレビュー**（追加・更新・エラー件数）
3. 利用者が確認して確定 → 取込（`import_jobs` に記録、取り消し可能な単位で処理）

出力は権限 `data.export` を持つ人のみ。出力操作は操作履歴に記録。

## 4. 連携アダプタの共通形（概念）

```ts
interface IntegrationAdapter {
  id: string;                         // 'csv-staff', 'line-works-notify' など
  capabilities: ('import' | 'export' | 'notify' | 'sync')[];
  validateConfig(config: unknown): Result;
  // import: 外部データ → 共通の取込形式（プレビュー → 確定）
  // notify: 通知内容 → 外部チャネル送信
}
```

外部から受け取るデータは常に「取込候補」として検証・プレビューし、自動で正式データを書き換えない。
