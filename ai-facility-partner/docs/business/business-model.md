# 事業モデル

- 版：v2（2026-11-17 設計レビューの指摘を反映：提供価値、統計情報の利用、効果の測り方）

> 本書の数値・価格はすべて**仮説**。実証施設での検証により更新する。

## 1. 一言で

介護施設の「運営業務（期限・依頼・提出物・証拠・委員会・研修）」を一元化し、施設長・事務長の管理負担を減らすとともに、**基準を満たさないことによる減算・返還のリスクを下げ、運営指導で記録と証拠を示せる状態**をつくる月額制クラウドサービス。AIは蓄積された業務情報を根拠に管理者を支援する。

## 2. 顧客と課題

| 顧客 | 立場 | 主な課題 | 提供価値 |
|---|---|---|---|
| 施設長 | 主な利用者・導入決裁に関与 | 施設全体の進捗が見えない。期限漏れ・提出漏れが運営指導で問題化する | ダッシュボードで今日・今週・超過・承認待ちが一目で分かる |
| 事務長 | 主な利用者 | 提出物の回収・督促・書類探しに時間を取られる | 自動リマインド、提出状況表、書類の一元検索 |
| 介護主任・部署管理者 | 利用者 | 依頼・回収・委員会の改善事項が口頭・紙で散逸 | 部署単位の業務依頼・進捗管理 |
| 一般職員 | 利用者 | 何をいつまでに出すか分からない | スマホで自分の業務・提出物だけを確認・提出 |
| 理事長・法人本部 | 契約者（複数施設法人） | 施設ごとの運営状況を比較・把握できない | 法人横断の進捗把握（PHASE 7） |

## 3. 競合との位置づけ

| 種類 | 例 | 当社との違い |
|---|---|---|
| 介護記録・請求ソフト | 各社介護ソフト | 利用者（入居者）の記録・請求が中心。施設運営業務（委員会、提出物、期限）の管理は対象外が多い → **置き換えず共存** |
| 汎用タスク管理・グループウェア | 汎用ツール | 介護施設の年間業務テンプレート・委員会・研修・証拠管理の型がない |
| 介護書類作成AI | 書類作成支援サービス | 書類の作成支援が中心。業務の期限・依頼・証拠の一元管理とは異なる |

差別化の軸：**介護施設の運営業務テンプレート＋証拠の紐付け＋根拠付きAI**。テンプレートの改善に施設の利用状況を使う場合は、個人を特定できない統計情報に限り、契約で範囲を明記する（委託の範囲を超えた利用にならないよう要専門家確認。`architecture/security-design.md` 第10章）。

## 4. 収益モデル（仮説）

- 法人単位の月額契約（施設数・職員数・利用モジュールで段階制）。詳細は `pricing-strategy.md`
- 初期費用：導入支援（年間業務の初期登録・職員登録）を有償オプションとする案
- 従量課金は初期段階では行わない（AI利用は上限内で定額）

## 5. 主要指標（KPI）

| 段階 | 指標 | 目標（仮） |
|---|---|---|
| 実証（PHASE 5） | 施設長・事務長の週あたり利用日数（利用記録から算出） | 週5日 |
| | 職員の提出物の期限内提出率 | 導入前比で改善 |
| | 管理業務の削減時間 | 施設長・事務長で月10時間以上（導入前2〜4週間の作業時間記録と比較。方法は `product/product-roadmap.md` 第3章） |
| | 職員のログイン率・代理登録率 | ログイン率の上昇、代理登録率の低下 |
| | 期限超過件数 | 導入前比で減少 |
| SaaS化（PHASE 6） | 継続率（解約しない割合） | 月次解約率1%未満 |
| | 導入から本稼働までの日数 | 30日以内 |
| 拡大 | 契約施設数・シェア | 長期でシェア40%（`target-market.md`） |

## 6. 成功の条件と主要リスク

| 項目 | 内容 |
|---|---|
| 成功の条件 | 最初の施設で毎日使われること。施設長・事務長の「なくては困る」状態をつくる |
| リスク1 | 職員がログインしない → ホームから3タップ以内で提出できる UI、アプリ外の通知手段（D-1）、共用タブレット方式（D-2）、紙の回収を記録する代理登録 |
| リスク2 | 初期登録の負担 → 出典付きの標準テンプレートと登録代行（D-9）、CSV 取込、未確認の要件の一括確認 |
| リスク3 | 個人情報・セキュリティへの不安 → ガイドライン準拠のチェックリスト、国内保管、説明資料 |
| リスク4 | AIの誤回答による信頼低下 → 根拠表示必須、推測しない設計、人の承認 |
| リスク5 | 制度改定 → 法令根拠はデータで管理し、確認者・確認日を記録 |
