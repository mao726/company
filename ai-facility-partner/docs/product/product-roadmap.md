# プロダクトロードマップ

期間は目安。PHASE 0 の質問（Q1〜Q6）の回答、実証施設のヒアリング時期によって変わる。各フェーズはテストと確認を終えてから次へ進む。

## 1. 指示書のフェーズとの調整（承認が必要）

指示書の PHASE 2・3 の分け方には、そのままでは実装できない依存関係がある。以下の調整を提案する。

| 指示書 | 問題 | 提案 |
|---|---|---|
| 提出物回収（PHASE 2）は「承認・差し戻し」「期限前の通知」を含むが、承認機能・通知は PHASE 3 | PHASE 2 だけでは提出物回収が完成しない | **承認（1段階）とアプリ内通知の基本部分を PHASE 2 に前倒し**。PHASE 3 で多段階承認・メール通知・通知タイミング設定画面を追加 |
| 操作履歴は PHASE 3 | 後から追加すると PHASE 2 期間の記録が残らない（監査上の欠落） | **記録は PHASE 2 の最初から**。閲覧画面を PHASE 3 |
| ダッシュボード（PHASE 2）に「委員会・研修予定」「AIからの確認事項」 | 委員会は PHASE 3、AI は PHASE 4 | PHASE 2 は「委員会・研修」カテゴリの業務を予定として表示。確認事項は「自動チェック（AIではない）」として表示。PHASE 3・4 で本来の機能に置き換え |
| 権限管理（PHASE 2） | カスタムロールまで作ると PHASE 2 が重い | PHASE 2 は標準6役割と割当、カスタムロール作成画面は PHASE 3（データ構造は PHASE 2 で用意） |

## 2. フェーズ別の内容と完了条件

| フェーズ | 期間目安 | 主な内容 | 完了条件 |
|---|---|---|---|
| PHASE 0 | 完了 | 現状調査 | 報告済み |
| PHASE 1 | 1〜2週 | 本設計文書一式、未決事項の解消 | **事業責任者の設計承認** |
| PHASE 2a 基盤 | 3〜4週 | プロジェクト雛形・CI、DB・RLS、認証・MFA、法人・施設・業態・設定、職員・所属・ユーザー、役割・権限、契約判定、操作履歴記録、ファイル基盤 | 必須テスト 1・2・3・8・12（基盤部分）合格 |
| PHASE 2b 業務 | 4〜5週 | 業務・状態遷移・承認（1段階）、繰り返し生成・年間業務・テンプレート・年度更新、業務依頼、提出物回収（代理登録含む）、書類管理、カレンダー、ダッシュボード、アプリ内通知、職員・年間業務のCSV取込 | 必須テスト 4・5・7・11 合格、架空データで業務一巡 |
| PHASE 3 | 4〜5週 | 委員会・研修・要件一覧、多段階承認、メール通知・通知タイミング設定、操作履歴画面、CSV出力、カスタムロール | 必須テスト 6・10 合格 |
| PHASE 4 | 4週 | AI接続層、施設運営AI（質問回答）、文書読み取り・分類・抽出、議事録下書き、改善提案、AI利用状況画面 | 必須テスト 9 合格、AI評価基準達成 |
| 実データ前の準備 | PHASE 3〜4 と並行 | セキュリティチェックリスト（専門家確認）、契約、脆弱性診断、復元訓練、ホスティング確定 | `architecture/security-design.md` 第6章の全項目 |
| PHASE 5 | 2〜3か月 | 実証施設での運用、効果測定、改善 | 削減時間の測定結果、継続利用の意思 |
| PHASE 6 | 別途計画 | セルフ登録、施設追加、プラン・オプション管理画面、利用状況、オンボーディング、データ移行 | |
| PHASE 7 | 別途計画 | 法人横断、職員・シフト、会議音声AI、外部連携、老健等の業態追加 | |

PHASE 5 を待たずに、PHASE 2b 完了時点から架空データで実証施設に画面を見ていただき、意見を反映する（作り込み過ぎの防止）。

## 3. 作らないもの（現時点）

- 入居者（利用者）の介護情報・医療情報を扱う機能
- 介護ソフト・請求ソフトの置き換え
- 複雑な従量課金
- AI による自律的な登録・通知・承認
- ネイティブアプリ（スマホ対応Webで対応）
- 外部連携（CSV で代替）
